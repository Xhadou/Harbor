# Harbor for Mac: full audit, 2026-11-20

Asked for after the release build was tried: "inspect from the language screen to the end and find all these errors", on the assumption that the screens inherited from Harbor were never finished to a standard.

How each item was established:

- **S** seen in a capture of the running app (dev build, 1280×800 window, interface at 80%)
- **B** seen in a clean first-run copy in a test browser (macOS styling on, no native sidebar)
- **M** measured from inside the running app
- **C** read in the code, not exercised

Captures are in the session scratchpad (`ob-*`, `a-*`, `b-*`, `d-*`, `e-*`, `p-*`), not in the repo.

## A. The four things reported

1. **Fullscreen "refuses to exit".** (M, S) The app keeps its own fullscreen flag and never listens to the window. Entering fullscreen with the green button, View › Enter Full Screen or Ctrl-Cmd-F leaves the flag off, so the player's fullscreen button shows "enter" and its first press does nothing; only the second press exits. Measured: system enter → window fullscreen, flag false → one button press → still fullscreen. `src/lib/fullscreen-state.ts`, `src-tauri/src/fullscreen.rs` (emits `fs://entered` / `fs://exited`, nothing subscribes).
2. **Top bar glitch after fullscreen.** (S, M) The reverse case. Leave fullscreen through the system and the flag stays on, so the player keeps its fullscreen layout in a normal window: Back and the title are drawn underneath the traffic lights. Capture `e-fs-sysexit`.
3. **In system fullscreen the player still thinks it is windowed.** (S) A 92 pt gap stays reserved for traffic lights that are not there. Capture `e-fs-sysenter`.
4. **Tab shortcuts.** Three separate causes:
   - (C) Every in-app shortcut is bound to Ctrl, none to Cmd: 11 defaults (`ctrl+=`, `ctrl+-`, `ctrl+0`, `ctrl+s`, `ctrl+l`, `ctrl+h` …), and section switching is Ctrl+Tab / Ctrl+1–9 with Cmd explicitly rejected. `src/lib/hotkeys.ts`, `src/chrome/tab-hotkeys.tsx`.
   - (C) Only five sections have a Cmd shortcut (Go menu, Cmd+1–5). There is no next/previous section (Cmd+Shift+] / [).
   - Corrected 2026-11-20: I first wrote that a click in the native sidebar keeps keyboard focus away from the page. It does not: `SidebarHost` already hands focus back after a selection.
   - Cmd+Tab itself belongs to macOS (app switcher) and cannot be an in-app shortcut.

## N. What runs through all of it

- **Every feature is on, everywhere.** Setup, a title page, the player bar and the library each expose everything the app can do at once. Nothing was cut.
- **No shared parts.** Five heroes, three title pages, three Play buttons, three heading sizes, four card heights. Each screen was built on its own.
- **Raw data shown as-is.** Codec names, channel layouts, addon strings with emoji, API keys, relay servers, debrid services.
- **Keyboard and focus were not designed.** Escape works in some overlays and not others; dialogs do not hold focus; shortcuts are Windows ones.
- **Unexplained numbers and badges.** "≡ 7", "TOP 43", "1 —", day counts, "M", "+5".
- **Small spaced capitals as labels**, used for everything from section names to warnings.
- **No shared rules for size, spacing or focus.** See 84 and 96: each new screen added its own values and its own override, which is why some screens look careful and the next looks improvised.

## Phase 1 status (done 2026-11-20, uncommitted)

Verified by measurement in the dev app unless noted.

- Fullscreen (1–3): the native window now reports every change (`mac-native://fullscreen`), and the page's flag follows it. System enter, system exit, the player button and Escape all agree; the button acts on the first press. On macOS the player no longer drops full screen at close if the window was already full screen when playback started.
- Shortcuts (4): on macOS Settings is ⌘, and interface scale is ⌘= ⌘- ⌘0; lock controls is ⌘L; the Go menu gained Next Section ⇧⌘] and Previous Section ⇧⌘[. Shortcuts the user rebound are untouched. Bindings are written the Mac way (seen on the shortcuts page). The menu items were not pressed by hand.
- Escape (62, 63): closes the Audio, Subtitles, Speed and Cast menus without raising the leave prompt.
- Dialogs (23, 24): the sign-in dialog closes on Escape and Tab stays inside it (test browser). The shared modal shell got the same Tab rule, so every dialog built on it has it.
- Blue box (84): gone on macOS; the field itself gets a soft ring (test browser).
- Output: revenue (39), audio track names ("English · DTS · 5.1", "Dolby Digital") (60), biography markers (134), "End of film" as the only end-of-title sleep option on a film (64).
- Setup (6, 141): every step fits a 960×600 window; a tall step scrolls inside its card (test browser).
- Library (74, 115): by design the Library tab lists saved titles only; the empty text I wrote said otherwise and is corrected. The header copy and the nine tabs are Phase 6.
- Not changed: "Leave the show?" wording (63), the Cast button not toggling closed (66).
- Reported by the user during this phase and fixed: a straight edge beside the sidebar's top corner over a hero. The titlebar fade added on 2026-11-20 began at the content edge while the hero runs on under the glass; it now spans the window (test browser).
- `scripts/mac-build.sh` failed on its second run (it left the mpv helper as a link, and staging will not copy a file onto itself); it now drops the link first.

Checks: typecheck, format and lint clean; `pnpm test` 8,266 pass, 5 fail (the same five as before this work); `cargo check` and the menu tests pass; `swift build` passes.

## Action plan

Design changes are scoped to macOS (`html[data-os="macos"]`, `isMacDesktop()`), as everything in this fork has been. Plain defects in shared code (39, 60, 134) are fixed for every platform. Each phase ends with a look at the real app, including a fresh install at 960×600 and 1280×800.

**Phase 1. Defects, no design decisions.**

- One source of truth for fullscreen: the page follows the window's state instead of keeping its own flag (1–3).
- Keyboard: hand focus back to the page after a sidebar click; on macOS bind the Ctrl shortcuts to Cmd; add next and previous section (4, 103).
- Escape closes every menu and dialog; dialogs take focus when they open and keep it (23, 24, 62, 63, 66).
- Remove the blue box; one focus style for fields (84, 85).
- Wrong or raw output: revenue (39), audio track names (60), biography markup (134), "show" and episode options on films (63, 64, 140).

**Phase 2. Shared parts, built once.**

**Phase 3. Player.**

- Bar: play, back and forward 10 s, volume, time, subtitles and audio, speed, AirPlay or cast, picture-in-picture, fullscreen. Everything else moves into one "more" menu. One button size, labels on hover, menus open above their button (55–59, 65, 68).

**Phase 4. First run and first Play.**

- Four steps in one card size: language, sign in, add a streaming source (new, with one plain explanation), done. TMDB key, streaming logos, subtitle languages and taste picks move to Settings.

**Phase 5. One hero, one title page.**

- One hero used on Home, Movies, Shows, Anime and Discover (28, 37, 38).

- Settings on macOS: about eight pages (General, Account, Playback, Subtitles and languages, Sources, Appearance, Shortcuts, Advanced). The rest are hidden or behind "Show all settings" (97, 121, 123, 124).

**Decisions that are the user's** (my default in brackets):

1. Player bar contents (the list in phase 3).
2. Which Settings pages survive on macOS (the eight in phase 6, the rest behind "Show all settings").
3. Whether the peer-to-peer engine starts with the app (no: start it when a peer-to-peer source is played) (122).
4. Whether automatic source choice should avoid very large files on a laptop (yes: prefer 1080p or under 25 GB unless told otherwise) (73).
